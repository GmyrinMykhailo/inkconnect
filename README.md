# Система сопровождения услуг бодимодификаций

Кроссплатформенное клиент-серверное приложение для поиска мастеров, записи на процедуру, получения рекомендаций по уходу и ведения защищённого журнала ухода.

## Возможности

- регистрация и авторизация пользователей;
- роли клиента и мастера;
- поиск мастеров;
- просмотр публичного профиля мастера;
- публикации и портфолио мастеров;
- добавление мастеров в избранное;
- запись клиента на процедуру;
- подтверждение и отклонение записей мастером;
- создание рекомендаций по уходу;
- подтверждение рекомендаций клиентом;
- ведение защищённого журнала ухода;
- фиксация событий журнала;
- проверка целостности журнала;
- чат клиента и мастера;
- загрузка и хранение медиафайлов через S3-совместимое хранилище MinIO.

## Технологии

- Flutter — клиентское приложение;
- Go — серверная часть;
- PostgreSQL — хранение структурированных данных;
- MinIO — S3-совместимое файловое хранилище;
- Docker Compose — запуск окружения;
- REST API — взаимодействие клиента и серверной части.

## Требования для запуска

Перед запуском должны быть установлены:

- Docker Desktop;
- Git, если проект скачивается через `git clone`.

Также должны быть свободны порты:

- `8088` — web-клиент;
- `18080` — backend API;
- `5433` — PostgreSQL;
- `9000` — MinIO API;
- `9001` — MinIO Console.

## Настройка окружения

В проекте есть файл `.env.example` с примером переменных окружения.

Для локального запуска через Docker Compose отдельная настройка `.env` не обязательна: в `compose.yaml` уже указаны значения по умолчанию для PostgreSQL, MinIO и backend.

Если нужно явно задать параметры окружения, можно создать файл `.env` на основе примера:

```powershell
Copy-Item .env.example .env
```

После этого при необходимости можно изменить значения в `.env`, например параметры S3/MinIO или ключ шифрования подписей журнала.

Файл `.env` не следует публиковать в открытом репозитории, так как он может содержать локальные пароли и секретные значения.

## Получение проекта

```powershell
git clone https://github.com/GmyrinMykhailo/inkconnect.git
cd inkconnect
```

Если проект передан архивом, нужно распаковать архив и открыть корневую папку проекта в терминале.

## Запуск проекта

Из корневой папки проекта выполнить:

```powershell
docker compose up -d --build
```

Команда соберёт и запустит контейнеры:

- PostgreSQL;
- MinIO;
- backend;
- web-клиент.

## Проверка запуска

Открыть web-приложение в браузере:

```text
http://127.0.0.1:8088
```

Проверить backend:

```powershell
curl.exe http://127.0.0.1:18080/healthz
```

Проверить файловое хранилище:

```powershell
curl.exe http://127.0.0.1:18080/api/v1/storage/health
```

## Адреса сервисов

Web-приложение:

```text
http://127.0.0.1:8088
```

Backend API:

```text
http://127.0.0.1:18080
```

MinIO Console:

```text
http://127.0.0.1:9001
```

Данные MinIO по умолчанию:

```text
Логин: inkconnect
Пароль: inkconnect_minio_dev_password
```

## Остановка проекта

```powershell
docker compose down
```

## Полная очистка данных

```powershell
docker compose down -v
```

Важно: команда удаляет все данные контейнеров, включая пользователей, мастеров, публикации, записи, журналы ухода и загруженные файлы.

## Повторный запуск

После обычной остановки:

```powershell
docker compose up -d
```

После изменений в коде или Dockerfile:

```powershell
docker compose up -d --build
```

## Примечания

- Файловое хранилище MinIO используется как private bucket.
- Клиентское приложение не получает прямые публичные ссылки на MinIO.
- Изображения выдаются через backend.
- PostgreSQL хранит структурированные данные и метаданные файлов.
- MinIO хранит сами файловые материалы.
